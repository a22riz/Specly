# Docs Tidy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the repo's documentation back to one consistent story after the PRD review pass landed, and give `docs/superpowers/` a navigable index — without deleting raw history.

**Architecture:** Docs-only. Two independent deliverables: (1) fix the statements that are stale or contradict the code; (2) add `docs/superpowers/README.md` and link it. No product code, no schema, no dependency.

**Tech Stack:** Markdown docs only. `docs/` is English; `README.md` and in-app copy are Indonesian.

**Spec:** `docs/superpowers/specs/2026-11-13-docs-tidy-design.md`

## Global Constraints

- Docs-only change. No file under `app/`, `lib/`, `components/`, `tests/` is touched.
- `docs/` stays English. `docs/architecture.md` is the canonical map; other docs defer to it.
- Do not move, rename, or delete any existing spec or plan file.
- Match existing doc voice: tables for lists, short imperative prose.
- Every path referenced in a doc must resolve to a real file in the tree.

## Review Focus

Docs have no test runner; the checks below are greps and path checks. The failure modes most likely to bite a reader:

1. A link or path that no longer resolves (`docs/superpowers/README.md` rows, cross-doc links).
2. A claim that contradicts the tree (module/component/page lists, suite count, versions).
3. A recipe that teaches a pattern another doc forbids (ownership fetch).
4. The three flow one-liners drifting apart again.

Each is pinned to a check in the owning task.
